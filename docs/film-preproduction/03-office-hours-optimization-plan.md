# Office Hours Optimization Plan

Generated by `office-hours` on 2026-05-14

Mode: Builder / research project

Status: approved working design for next planning pass

## Problem Statement

This repo is trying to turn one short user idea into professional film preproduction artifacts, then into image prompt packs and model-specific video prompts.

The current docs already define the broad system. The missing layer is the execution contract that lets Goal mode or gstack skills continue the work without guessing.

## What Makes This Worth Building

Most AI video workflows start too late.

They jump from a vague idea to a prompt, then blame the model when the result is weak. The better wedge is preproduction: force the system to think like a small director room before it writes prompts.

That means the useful product is not "better prompt writing." It is:

```text
idea -> professional creative development -> structured shot plan -> reference image pack -> model-specific video prompt -> QA/retry loop
```

## Premises

1. `Prompt Compiler` is not the product. It is the last stage of the preproduction pipeline.
2. Each stage must produce structured artifacts that the next stage can consume.
3. Different channels need different development logic. Film, ads, short drama, short video, and MV cannot share one generic structure.
4. Different video models need different prompt adapters. A universal video prompt will produce unreliable output.
5. Sound must be handled as a first-class planning layer. Image prompt, video prompt, and post-production audio are separate.
6. Goal mode needs machine-readable phase contracts, not just narrative roadmap prose.

## Current Strengths

- Strong scope boundary: no direct video generation yet.
- Strong domain direction: film preproduction first, prompt compiler later.
- Useful first fixture: `cyber-courier` is small enough to validate the chain.
- Schema layer exists for director room, story, shot list, visual bible, image prompt manifest, video prompt manifest, and QA.
- Research files already separate production knowledge, model guidance, audio policy, channel strategy, and storyboard/reference board rules.

## Current Gaps

### Gap 1: The roadmap is readable but not executable enough

The roadmap lists phases and artifacts, but a Goal-mode agent needs stricter contracts:

- current phase,
- allowed edits,
- required inputs,
- required outputs,
- verification commands,
- done conditions,
- handoff summary.

Fix:

Create `docs/film-preproduction/04-goal-mode-handoff.md` and `docs/film-preproduction/phase-contracts.yaml`.

### Gap 2: No explicit skill routing map

The repo says which modules should exist, but not which gstack/superpowers workflow should be used when.

Fix:

Add routing guidance:

```text
office-hours -> architecture and premise checks
plan-ceo-review -> ambitious scope and product value critique
plan-eng-review -> architecture, contracts, testability
writing-plans -> detailed implementation plan
executing-plans or subagent-driven-development -> implementation after plan approval
verification-before-completion -> final checks
```

### Gap 3: Professional quality is not yet testable

The docs say "professional", but a worker needs observable checks.

Fix:

Define evaluation fixtures:

- Can an agent distinguish 5-shot director board from 3x3 storyboard grid?
- Can it write shot list fields without vague "cinematic" filler?
- Can it separate image prompt audio notes from video prompt audio execution?
- Can it create different Seedance/Kling/Runway/Veo prompts from the same shot list?
- Can it identify when a board is too dense for video model use?

### Gap 4: The reference pack is under-specified for WYSIWYG

The plan mentions a future frontend, but the data model should already support it.

Fix:

Add artifact IDs and run IDs:

- `project_id`
- `artifact_id`
- `source_artifact_ids`
- `version`
- `status`
- `locked`
- `approved_by_user`

Without these, a future frontend will mix old and new states.

### Gap 5: Model adapter knowledge will go stale

Seedance, Kling, Runway, and Veo behavior changes. The repo needs a refresh policy.

Fix:

Each model adapter note must include:

- verified date,
- source URLs,
- stable facts,
- inferred behavior,
- refresh trigger,
- adapter risk.

## Approaches Considered

### Approach A: Keep extending docs phase by phase

Summary:

Continue writing research docs, schemas, and examples in order.

Effort: S

Risk: Low

Pros:

- Fast.
- Keeps momentum.
- Good for thinking through the domain.

Cons:

- Still relies on the current agent to infer task boundaries.
- Weak handoff to Goal mode.
- Can drift into prose-only planning.

### Approach B: Contract-first Goal-ready system

Summary:

Add phase contracts, Goal-mode handoff, artifact IDs, verification commands, and explicit gstack routing before continuing the example.

Effort: M

Risk: Low

Pros:

- Makes the repo executable by future agents.
- Prevents premature prompt generation.
- Makes "done" observable.
- Creates a clean bridge to Goal mode and gstack skills.

Cons:

- Slightly slower than just continuing the example.
- Requires discipline to keep contracts updated.

### Approach C: Build the WYSIWYG workbench early

Summary:

Start prototyping the frontend workbench now and let UI needs force the schema.

Effort: L

Risk: High

Pros:

- Makes the idea tangible.
- Reveals real user workflow issues.
- Good for future product demo.

Cons:

- Too early.
- Risks building UI around unstable artifacts.
- Pulls focus away from the professional film workflow knowledge base.

## Recommendation

Choose Approach B.

The repo is now at the point where more prose has diminishing returns. The next useful thing is an execution contract that makes future Goal-mode workers hard to confuse.

## Recommended Architecture Adjustment

Add a control layer above the existing docs:

```text
00-goal-mode-handoff
phase-contracts.yaml
research/*
schemas/*
examples/*
qa/*
skills/*
```

Control layer responsibility:

- say what phase is active,
- define what files may change,
- define what artifacts must exist,
- define how to verify them,
- define what is out of scope.

Content layer responsibility:

- professional film knowledge,
- model adapter knowledge,
- channel rules,
- schemas,
- examples.

Skill layer responsibility:

- convert stable docs into reusable Codex/Claude skills later.

## Revised Roadmap

### Phase A: Goal-ready contract layer

Output:

- `docs/film-preproduction/04-goal-mode-handoff.md`
- `docs/film-preproduction/phase-contracts.yaml`
- README updated with Goal-mode entrypoint.

Done when:

- a fresh agent can read one handoff file and know exactly what to do next,
- every phase has inputs, outputs, allowed edits, verification, and done conditions.

### Phase B: Story fixture completion

Output:

- `examples/cyber-courier/05-logline.md`
- `examples/cyber-courier/06-beat-sheet.md`
- `examples/cyber-courier/07-treatment.md`
- `examples/cyber-courier/08-story-review.md`

Done when:

- story is coherent,
- no image prompts are written,
- story review says whether it can proceed to script.

### Phase C: Script and breakdown fixture

Output:

- `09-script.md`
- `10-script-breakdown.yaml`
- `11-asset-requirements.md`
- `12-audio-policy.md`

Done when:

- every script element is accounted for in breakdown,
- audio policy is explicit,
- missing asset list is empty or intentionally deferred.

### Phase D: Shot design fixture

Output:

- `13-shot-list.yaml`
- `14-camera-plan.md`
- `15-blocking-plan.md`
- `16-shot-qa.md`

Done when:

- every shot has duration, shot size, lens, camera motion, action, blocking, sound, and narrative purpose,
- QA catches overloaded shots.

### Phase E: Visual bible and reference pack

Output:

- `17-visual-bible.md`
- `18-reference-pack-plan.yaml`
- `19-image-layout-spec.md`

Done when:

- reference pack is split by role,
- single-board vs multi-pack decision is justified,
- no panel relies on unreadable tiny text.

### Phase F: Prompt compiler design

Output:

- image prompt manifest,
- image prompt examples,
- image prompt QA checklist.

Done when:

- prompts are model-safe,
- exact labels are specified,
- prompt avoids fake text, decoration, and undersized panels.

### Phase G: Video model adapters

Output:

- Seedance prompt,
- Kling prompt,
- Runway prompt,
- Veo prompt,
- adapter risk notes.

Done when:

- prompts differ materially by model,
- each prompt maps reference images,
- audio policy is explicit,
- anti-misread clause exists.

### Phase H: Skill packaging

Output:

- initial skill folder structure,
- `SKILL.md` for each stable module,
- examples and tests.

Done when:

- skill boundaries match artifact contracts,
- no skill tries to do the whole pipeline,
- QA fixtures prove behavior.

### Phase I: WYSIWYG workbench

Output:

- product/interface spec,
- data flow,
- prototype plan.

Done when:

- frontend reads artifact IDs and versions,
- user can lock decisions,
- generated prompts are traceable to source artifacts.

## Goal Mode Entry Contract

Goal mode should start with:

```text
Read README.md.
Read docs/film-preproduction/04-goal-mode-handoff.md.
Read docs/film-preproduction/phase-contracts.yaml.
Do only the active phase.
Do not skip ahead to prompt generation.
Do not create image or video assets unless the active phase explicitly allows it.
Run the listed verification commands.
Commit only after verification passes.
```

## Recommended gstack Sequence

Use this order:

```text
/office-hours
-> /plan-ceo-review
-> /plan-eng-review
-> /autoplan or /writing-plans
-> /executing-plans
-> /verification-before-completion
-> /checkpoint
```

Do not use `/ship` until this is a real plugin/skill package with tests.

## Open Questions

- Should this stay as a local Codex/Claude skill package, or become a reusable public plugin?
- Should model adapters produce only prompts, or also parameter recommendations?
- Should the first frontend be a file-driven local workbench or a browser app?
- Should source refresh be manual per run or automated per adapter?

## Success Criteria For Next Handoff

The next agent should be able to:

1. Identify current phase without asking.
2. Know which files it can edit.
3. Know which files are out of scope.
4. Produce required artifacts.
5. Verify schema validity and no placeholder text.
6. Commit a clean, scoped change.

If it cannot do those six, the architecture is not clear enough yet.
