# DIRcreative 工作流、协作与专业能力优化

本轮为源码维护，基于 0.8.0 的未发布工作区改动。目标是让 Codex 按用户要求完成实际创作、资产和提示词工作，同时减少无效确认、重复加载和控制记录。本轮没有生成新图片/视频，没有覆盖正式安装，也没有执行发布。

## 它承担什么工作

DIRcreative 是影视前期与 AI 生成工作的专业编排入口：从简报、既有剧本或参考片，发展故事、对白与声音、镜头和表演、资产与参考职责，最后产出对应模型的可用输入。用户明确要求真实资产时，还需通过可用媒体工具执行并审查。它保留创作事实与版本，把当前专业环节交给合适的 Skill，再收回实际结果。

它应支持不同规模的交付：一句对白直接改；客户故事写成完整可读文字；完整前期连续完成所需剧本、镜头、资产与提示词；失败镜头只修受影响的来源和后续依赖。提示词、图片生成、图像审查、用户接受、最终视频与外部交付是不同结果。

## 发现与实际改动

| 问题 | 改动与保留边界 |
| --- | --- |
| 主路由全部禁止 Threads，显式导演组/创意组/并行没有对应执行描述 | 现有 router 增加 collaboration 合同。点名组使用专业视角；明确联合/并行使用真实宿主子代理，默认最多两个；新用户任务仍须明确请求。没有工具时报告阻塞，不能虚构已派发。 |
| 另一套关键词 selector 把“完整影片，先给一句概念”降为 Fast，或漏掉普通多产物请求 | 专业视角消费主路由；已有 ADCO worker 路由可直接传入，避免重新开组。 |
| 否定生成/外发也进入审批；解决后的冲突反复确认；单镜头误升 Studio；一页单方向故事被扩为全片 | 增加正向、否定、引用、比较、维护、真实 handoff 和范围层级回归，修复对应分支。 |
| 旧内部模块强制 brief、故事、剧本、分镜、视觉、参考图逐一确认 | 子模块回归按需专业环节；已有授权继续，只有实际未解决方向或未批准副作用才询问。旧 v1 示例保留为历史兼容材料。 |
| 正式 humanization 链变成普通写作的前提；所有影片被套入同一种戏剧结构 | 普通写作和短改直接使用语言工艺。系统性缺陷/显式方法再进入分层改写；抒情、观察片按感知、节奏和关系推进验收。 |
| 本机能用的 system imagegen 与包内 stress/ledger 没进入生产发现链 | 仅增加授权根下一层 .system 和当前包内两个精确 ID；支持安装后 INTERNAL_SKILL.md，保持真实正文/hash、重复与禁用处理、路径边界和延迟读取。 |
| 正常人物连续性 collaborator 被入口上下文挤出，mock 小文件未暴露 | 精简入口与 Studio 指令，不提高预算；实际安装正文重放中，该 collaborator 现可进入 20 KB 主上下文。 |
| 模型提示词包含内部资产 ID、项目 ID、来源 hash；标题约束误伤无字资产 | 控制信息保留在 execution packet/manifest；终端提示词只保留视觉事实、实际参考、画幅和角色所需文字。人物来源绑定和独立审查保持严格。 |
| 资产压力测试末阶段永久 needs_followup | 修正 provider capabilities 与 asset_stress_certification 的名称对接。只解除选择链的假缺口，真实资产的签名/视觉审查仍由原 validator 验证。 |
| 归档工作树被当成应删除；旧收据被用来检查不相关的当前工作树 | 历史验证默认不查实时 worktree；显式检查仅对明确声明应移除的路径生效，归档不是删除。 |
| 维护检查奖励旧会议词、强制确认句，实际内容变化难以验收 | 保留历史数据兼容测试，移除对现行模块的旧流程强制；加入原始用户请求的新进程评测，并分别记录内容、调用数、时间和模型证据。 |

## 专业 Skill 如何协作

| 环节 | 当前职责 |
| --- | --- |
| 资产基础 | minimum-visual-bible、character-continuity-bible 建立可复用身份/状态；production-design-worldbuilding、master-shot-camera-planning、材质和约束 Skill 按具体缺口分阶段工作。 |
| 图像资产与画面提示词 | 简单低风险图像使用简洁直接路径；复杂参考/布局/编辑和电影帧通过 Jingzao 的真实 spec 与编译器。传入完整真值、参考职责和允许变化，返回精确编译输出；Delivery 不能重写一次丢掉其判断。 |
| 视频提示词 | convert-script-to-seedance 保留权威剧本、表演容量、实体/素材编号、连续性与生成单元；Seedance 2.5 使用已核对的 mr-li-seedance-25 方法层。正式可执行 handoff 仍需要实际资产与对应 review；缺图草稿不能冒充通过编译。 |
| 审查与记录 | ai-video-prompt-preflight 检查提交前输入；ai-film-asset-stress-test 评估真实资产的可用范围；production-ledger 只记录最终候选与后续证据，不担任生成器或批准人。 |

实际本机发现重放从 137 条增至 145 条：补齐系统层 6 条与包内 2 条，未重新公开内部 Skill。入口源文件从 9,058 字节缩至 7,746 字节；Studio card 从 3,474 至 3,368 字节。该指标只说明需要读取的内容减少，不证明端到端速度或费用同比下降。

使用实际已安装 Jingzao 编译器，从零完成“红漆铜铃—顶部铜环—白色麻绳—旧木梁”的悬挂道具 spec 和 341 词提示词；编译审查与 call plan 为 ready。没有提供假图片，也没有调用图像生成；这个结果仅证明真实编译路径和文本约束保留。

## 验证与限制

- 253 项单元测试通过。本轮针对路由、目录发现、当前审计范围和提示词表面新增回归，并保留已有资产、来源、签名、scope、编译器和媒体证据测试。独立复审提出的问题已修复并复验。
- 原始请求进入独立 Codex 进程，使用字节一致的隔离安装候选，实际读取 Skill。请求模型为 gpt-6-astra / max；CLI 事件未回传可证明的实际模型 ID，因此报告只记录请求值。
- 四个文字案例实际完成：局部脚本修改、一页创意组故事、悬挂道具提示词、神话角色对白。最终答复的内容检查均通过、没有问题或流程说明，也未宣称媒体生成；完整会话包含宿主要求的过程更新。首次创意案例超时，保留失败记录；后续在较长的观测时限内完成，不能据此宣称耗时已经下降。
- 工具总数保留原始值。四例分别为 3/4/4/3 次，其中定位调用为 1/1/1/0 次；最后一例只是把必要参考分开读取。原始三项工具次数 FAIL 保留，不能把它们都归因于定位，更不能统一扣一次调用来变为 PASS。新的一页故事路线只读取小型 client-story craft，避免客户故事加载全片资产段落。读取、调用和内容结果分别报告。
- 一页故事改为专用 craft 后，针对性新进程复测通过；工具调用由 4 次变为 3 次。原始工具输出中实际读取的指令字节由 27,481 降至 18,263，减少约 33.5%，重新落入 20 KB 预算。该次耗时由 302.389 秒至 215.279 秒；这是单次观察，不能推出稳定提速或费用下降。
- 官方 quick_validate 脚本因本机缺少 PyYAML 未能直接运行；前置 YAML/JSON 与 Skill 结构由现有 Ruby/Python 项目校验覆盖，不为验证临时改动全局 Python 环境。
- 本轮没有验证新图片的像素质量、完整全片媒体生产、真实双子代理创作、用户采用或最终视频；路由测试不替代这些证据。
- 缺少宿主独立 review/adoption 时，必须尽早说明确切阻塞并保留可用设计与提示词，不能自制签名/回执换取完成状态。

## 后续调用

- 局部工作：`$dircreative 只修改这一镜的提示词，保留已有身份与空间。`
- 创意工作：`$dircreative 请创意组写完整客户故事，只要故事。`
- 真实协作：`$dircreative 请导演组和创意组联合完成故事、剧本、分镜与声音设计，普通取舍你决定。`
- 真实资产：明确图片与最终视频各自范围，并使用具备实际执行和独立审查接口的宿主。

正式安装未被这次源码维护替换。隔离安装与候选验证不等于已发布版本或全局 Skill 已更新。

方法依据包括实际本机代码、安装内容、历史《把雨还给天空》的零媒体/版本漂移复盘，以及当前 [OpenAI Skill 指南](https://learn.chatgpt.com/use-cases/reusable-codex-skills)。历史中止状态只用于设计回归，不作为当前候选仍然失败的证据。
