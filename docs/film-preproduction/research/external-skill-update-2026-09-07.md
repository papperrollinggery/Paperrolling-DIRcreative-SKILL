## Direct method integration

Seedance 2.5 compilation selects the exact audited 2.0 provider. Its body and
four production references are read and hash-bound: `prompt-writing`,
`continuity-and-duration`, `context-protocol`, and `segment-ending`. The observed
installation fits the existing isolated method budget. Full-flow regression
instructions, historical changelog and the 153,983-byte aggregate runtime are
not added to the production context. Relevant reference context is replaced
when the stage changes.

The provider contributes segment capacity, script fidelity, natural boundaries,
speaker/voice handling and concise model-facing prompts. DIR retains the source,
current state, asset/reference contracts, approved camera decisions, capability
cards and authorization. These limits travel in the provider's actual host
body-read request. Selecting or materializing it still reports host adoption as
unverified; real use must be shown in the produced work.

## Adapted methods and existing owners

| Delta since 1.9.0 | DIR adaptation | Verification boundary |
| --- | --- | --- |
| Cross-check scene heading, neighboring source and current state before production | Perform the check in shot/asset design before the affected image or prompt; unresolved contradictions stay with affected work, while independent work continues | A source/hash check cannot decide narrative truth; inspect the actual source and resulting prompt/image |
| Review suggestions and separate revisions do not silently become authoritative | Preserve the current adopted source in conversion; existing explicit creation/adoption authority remains valid | Exact source file and dialogue locators are checked; unadopted suggestions must be caught in source review |
| Source completion is independent of exported segment count | Bind the next unmade source line and its hash; the last exported unit can remain `segment_only` | Reject missing/stale/repeated dialogue locators; a null cursor still requires actual source coverage review |
| Voice references follow the speaking roles in each segment | Use the existing audio binding ledger, scoped by `voice_owner_entity_id` and unit; applicable alternatives are aggregated | Known applicable voice cannot be omitted; planned/unavailable media creates no fictional attachment or repeated question |
| Asset, blocking and storyboard-preview images serve different purposes | Map to existing identity/state, scene/FOV, narrative-frame and coverage roles | Previews do not become clean/model inputs automatically; supported annotated references retain their explicit DIR promotion gates |
| Medium and entity shape determine the visual vocabulary | Preserve the selected Jingzao medium and remove the legacy character helper's forced photorealism | Keep five human views and the structural probe; actual stylized/nonhuman image quality is not inferred from prompt tests |
| Clean master, candidate and adopted output are separate states | Register the exact native output against its prepared plan, then inspect a role-specific blank self-check template before the next asset | Self-check cannot grant independent QA, user adoption or completion; changed plans/pixels and pending checks block the controlled call path |
| Delivery is checked against the expected scope, not reverse-inferred from whatever files exist | Reconcile the original requested roles/units with the canonical inventory/plan and actual reviewed outputs | Plan coverage, saved pixels, visual quality, prompt delivery, video execution and acceptance remain separate |

The failure that prompted this repair also exposed missing natural-request
selection: storyboard plus “related assets” could bypass character design,
standalone assets could require unrelated film stages, and a generic legal
Jingzao compile could omit the active character role. The existing selector now
selects the relevant initial design; the existing execution handoff compiles its
canonical requirements into actual spec inputs. Role-specific observation and
registration live in the current visual plan, not a parallel ledger.

## Deliberately bounded provider rules

- Keep DIR's frontal portrait plus front/left/right/back full-body human master.
  The provider's three-body mixed headed/headless layout is not imported.
- Its longer-lens preference is advisory. It cannot rewrite a locked wide shot,
  POV, action camera, axis or shot purpose.
- Do not import blanket storyboard non-binding into DIR's deliberately supported
  annotated-reference route. Conversely, an attractive preview is not a promoted
  reference or literal first frame.
- Inherit all/key/skip choices and existing project structure. Do not impose
  seven-stage tutorials, repeated menus, new folder approvals or foreign IDs on
  an already scoped DIR task.
- Keep the provider external. Do not vendor its full runtime, audit scripts,
  model facts or state controller. Its file audit is not a substitute for DIR's
  source-bound coverage and media review.

## Focused checks

`test_collaboration_routing.py` and `test_skill_stack_route_context.py` cover
natural requests, negative scope, mixed reuse, quoted craft facts and initial
design without certification authority. `test_image_execution_postcheck.py`
covers generic-compile rejection, role replacement, exact native inputs,
registration after plan changes, pending/failed candidates and self-check/QA
separation. `test_mr_li_v2_integration.py` covers 2.0 selection/context/ownership,
source cursors, scoped voice alternatives and preserved visual medium.

These checks and actual installed-provider compilation are engineering evidence.
They do not establish image quality, future host adoption, video generation,
user acceptance or publication. A release must separately record the real
from-zero asset run, independent review and published-package installation.

A fresh text-only request read the installed 2.0 body and four references and
produced one natural segment retaining exact dialogue, the locked 24mm shot and
hard cut to black, without fictional media bindings. This is observed application
to that prompt, not a general host-adoption or video-quality claim. The from-zero
asset fixture separately records real image generation and actual visual defects;
its generated subset cannot stand in for the complete requested asset set.
