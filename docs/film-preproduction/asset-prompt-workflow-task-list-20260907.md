## 已确认的实现问题

1. `scripts/dircreative_visual_asset_jingzao_handoff.py:70` 的 `canonical_asset_role_requirements` 固定人物大肖像加四全身的布局；`:156` 的 `prepare_candidate_repair_spec` 先调用 `prepare_role_spec`，再切换 edit 模式，局部修复也重新注入上述生成要求。
2. 同文件 `role_spec_errors` 和最终 compiled prompt 检查要求完整 canonical 文句出现。只在上游缩短修图提示不能解决问题；准备器、验证器与实际编译契约必须一起改。
3. `scripts/dircreative_visual_asset_plan.py:1155` 的 `build_candidate_repair_source` 把当前 generated_file 绑定为修图底图，没有显式选择历史最佳母版的入口。这条路径不自动发起重试，但会约束调用者沿当前候选继续编辑。
4. `scripts/dircreative_asset_execution_gate.py:1457` 检查整份计划的候选；`pending_candidate_self_checks` 遍历所有登记资产，不按当前资产依赖筛选。`tests/test_image_execution_postcheck.py:181` 明确测试“待检查产品阻塞无依赖道具”。这是代码层的全计划门禁；案例实际还包含多个 asset_only 计划，因此不能把全部停滞都归因于这一个门禁，控制者的任务选择也要修。
5. 案例 v03 自检先批量填 pass 和通用描述，再覆写个别失败项，不能作为各视角和材质保留都经过充分检查的证据。现有文档已经禁止预填 pass，问题包括执行遵从与可观察验证，不是再加一句规则就能解决。

## P0：先停止冲突、退化和全片阻塞

### T01 — 让局部修图使用与操作匹配的提示词契约

- [ ] 修改准备器与验证器：区分首次创建、既有图局部修复、明确要求的重排/重设计；复用现有 mode/operation，不增加第二套路由。
- [ ] 局部修复保留源图实际布局，只有用户要求变更布局时才发出新布局要求。角色身份、材质和非对称设计的专业约束仍保留。
- [ ] 同步调整 canonical 文句强制检查，避免短修图提示被再次补成长篇整图生成要求。
- 范围：visual_asset_jingzao_handoff、相关 schema、test_candidate_repair、test_asset_prompt_surface、test_visual_asset_jingzao_handoff。
- 验收：用本次鼻朝向相反的源图布局建立 fixture；最终实际调用中不得同时出现保留排列与重排要求。对照新建四视图场景仍保留完整设计契约。

### T02 — 增加提交前的语义冲突检查

- [ ] 检查左右侧、视图编号、图像坐标、姿势、保留/修改范围是否互相矛盾；文字要求必须与附图的实际位置核对。
- [ ] 检查新参考是否已附上、是否只承担指定职责；避免更换风格后旧工装/姿势/布局要求继续进入调用。
- [ ] 已知模板冲突用确定性检查，开放的图像语义由目视判断；不宣称普通字符串校验能理解整张图。
- 范围：handoff 准备与验证、镜造编译交界、相关用例。
- 验收：本案例矛盾在生成前被指出并改正；正常短提示不因缺少通用长句被拦截。编译 ready 与视觉语义检查的覆盖边界分开记录。

### T03 — 修复底图选择与重试退出策略

- [ ] 区分最新候选、最佳保真基底、已采用版本；允许同资产、同有效设计状态的历史最佳图作为显式修复源，保留 lineage/hash，不用旧计划绕过当前事实。
- [ ] 发生“修好 A、破坏 B”或明显材质退化时，停止在最新候选上继续累积编辑，转为从基底重试、局部处理或延期该局部。
- [ ] 每个资产采用有限返工预算；建议首次失败后允许一次针对性修复，再失败必须重新诊断并推进可独立工作。具体轮数作为可调整生产策略，不当作模型普遍规律。
- 范围：visual_asset_plan、candidate repair 契约、执行指导与控制者状态。
- 验收：构造 v01→v02→v03 回退案例，下一步不再机械选择 v03；不会丢失已记录失败，也不会把历史底图伪装成已验收。

### T04 — 根据真实工具能力选择编辑范围

- [ ] 区分文字限定、显式遮罩、裁切局部输入、确定性合成能够提供的保证；工具未暴露参数时不虚构支持。
- [ ] 需要未改区域逐像素保持时，采用真实局部编辑加原图合成的实现方案；仍由图像模型生成修改内容，合成只负责保留原像素，并验证边缘、光照和尺寸。
- [ ] 工具仅支持整图参考编辑时明确不能保证保护，优先缩小输入范围或从固定基底制作替代版本。
- 范围：asset_execution_gate 及现有 provider 适配边界、image-execution 文档；必要时调整外部镜造维护源，不能仅改已安装缓存。
- 验收：检查实际请求参数和输出；如声明像素保护，非编辑区域必须经像素比较成立，不能用 prompt 中的 protected 作为证明。

### T05 — 将全计划阻塞缩小到真实依赖

- [ ] 当前资产及其实际依赖仍核验来源、自检和设计状态；无依赖资产可继续生成，欠缺检查仍在计划里可见。
- [ ] 区分缺失自检、已检查但有缺陷、设计事实失效与最终未验收，避免一个 retry 阻止所有工作。
- [ ] 替换“无依赖资产必须被阻塞”的现有测试，增加真实依赖必须阻塞的反例。
- 范围：pending_candidate_self_checks、prepare_image_call、test_image_execution_postcheck、执行文档。
- 验收：人物肩甲待修时场景/独立道具可推进；依赖该肩甲设计的正式镜头保持待解决；最终全片完成门禁仍检查所有必要资产。

### T06 — 让控制者持续选择全片未完成工作

- [ ] 每次生成与检查后，回到已有资产/镜头计划，选择下一项可执行任务，而不是默认修复当前图。
- [ ] 输出状态说明“已产出、待修、被什么依赖阻塞、下一项”；首批覆盖范围按项目决定，避免一张母版耗尽整个回合。
- [ ] 保留已完成剧本、机位、动作相位与参考研究，图像缺陷不使叙事阶段重启。
- 范围：studio-development route、现有 stage/gaps 选择与状态快照、image-execution 指导。
- 验收：从零运行包含人物、鸟、机关、场景、道具和分镜的临时项目；注入人物局部缺陷后，日志及真实产物都显示独立项继续推进，只把真实生成结果计为正式产物。

## P1：提高首轮质量与审阅有效性

### T07 — 在首次出图前形成明确视觉设计

- [ ] 有明确参考时先读图/视频证据，提取轮廓、材质层次、色彩和装饰结构；未知部分作合理设计判断，不反复让用户确认。
- [ ] 将项目事实、用户偏好、图像内容和制作管理信息分开；模型提示只保留对画面有效的信息。
- [ ] 编译结果应是一份无冲突、可独立执行的画面描述，而非字段越齐越好；不以字数减少代替质量改善。
- 范围：资产 intake、visual_generation_spec、reference-image-planner 与镜造输入交界。
- 验收：参考驱动的复杂服装首次请求就包含已研究的质感；与用户成功方法对照，检查原图、反推文本、附图、参数、实际输出，避免只比较两个提示词长度。

### T08 — 按用途选择母版形式，避免一次承担所有设计任务

- [ ] 允许按用途先产高质量单视图/关键结构，再推导必要侧背视图；用户明确要完整多视图时仍支持一次生成或分步汇总。
- [ ] 单视图设计稿与具备下游覆盖的正式母版明确区分；单视图不自动通过全视角连续性验收。
- [ ] 分别产出的视图最终可组成人物表，逐项检查身份、比例、材质与非对称部件，不能靠同名当一致。
- 范围：canonical_asset_role_requirements、人物模式/覆盖 schema、character visual gate、资产计划与对应测试。
- 验收：普通单图请求不被扩成四视图任务；需要背面镜头的项目确实有有效背面资产；实测比较两种制作方式后确定默认，不提前规定所有项目必须拆图。

### T09 — 审阅同时检查目标修复和非目标退化

- [ ] 与固定基底及上一候选同时比较：肩甲、脸、发丝、刺绣、纱料、金属边缘；自动指标只辅助定位，不给画质下最终结论。
- [ ] 区分风格偏好、真实连续性错误、技术探针失败；用户已接受的高跟靴和袖披不因通用动作模板被反复改掉。
- [ ] 自检 observations 必须描述实际可见证据；抽样独立检查通用 pass 记录是否可信，不用增加字段冒充可靠性。
- 范围：candidate_self_check 模板/执行指导、character visual gate 使用边界、generation QA。
- 验收：本案例 v03 不能只因背面正确而整体晋级；鼻朝左肩甲回退与非目标细节变化必须被保留为问题。

### T10 — 让资产改动只使受影响内容失效

- [ ] 利用现有依赖关系记录哪些镜头使用哪种外观/状态/侧面；局部变化仅要求相关资产与镜头重验。
- [ ] 暂用参考、局部待修、正式可用和用户采用分开；不通过重命名状态绕过连续性要求。
- 范围：现有 visual plan、coverage sidecar、继承和失效检查。
- 验收：改肩甲不重启剧本和独立场景；使用该侧面的镜头会收到明确重验要求，整片完成声明仍准确。

### T12 — 用真实工作流验证整套修改

- [ ] 测试组至少包括：参考反推单图、从零复杂人物资产、既有图局部修复、普通独立道具、不受本次修改影响的原有场景。

## 建议实施顺序

1. T01、T02、T05：先消除已确认的模板冲突和全计划阻塞，同时保留现有来源与安全校验。
2. T03、T04、T06：打断连续退化链，让控制者能够换方法并推进其他工作。
3. T07、T08、T09、T10：提高首次设计与审阅质量，完善局部失效传播。
4. T11 按复现结果修复；T12 从首批改动开始建立对照，最终用于验收整个候选。

避免以另建路由器、更多表单、更多审批和更多固定模板替代上述修复。也不删除摄影、空间、动作、材质与覆盖专业要求；这些要求应在正确阶段以适合当前操作的形式生效。
