# Production efficiency: preserve quality, remove protocol work

## Goal and observed baseline

Finish the user's requested content well and quickly. Preserve requested views,
identity, materials, reference responsibilities, actual output review and real
dependencies. Reduce the model's work assembling internal protocol documents.

The v0.9.4 first batch took 21m37s from its restart instruction to four saved
images. Four generation-containing tool cells totaled 3m18s (including some
preparation/registration). Before the first call, 11m38s elapsed; the task wrote
a 306-line adapter. After that batch it wrote a 78-line review script and took
another 17m before starting props. Non-generation time also includes legitimate
design/review and model latency; it is not all removable overhead.

## Strategy and implementation

1. Add a thin asset preparation entry point over existing role preparation,
   provider compilation/reference delivery, foundation evidence and execution
   validators. Input: current plan, asset, authored spec, optional selected style
   capsule and existing design evidence. Output: validated native call arguments
   and existing bound records. No new router or lifecycle; no generated success
   or visual acceptance may be invented. Keep create/repair boundaries explicit.
2. Remove duplicate review first, then expose a thin batch review entry point.
   A completed visual review of the same pixels/truth/use satisfies the pending
   candidate inspection; do not require a second executor checklist. Failed
   candidates keep the existing explicit defect/repair observations. Downstream
   reuse binds the source generation task, not a newly consuming task.
   The reviewer supplies real observations and decisions;
   hashes, manifest/receipt construction, valid status handling and plan updates
   are mechanical. A detector disagreement remains bound to the real receipt.
   Do not prefill a pass or bypass dependent-use authority.
3. Update the active instructions to use these entries. One substantive batch
   review serves production; reserve a second independent review for material
   unresolved risk or explicit requirements, not routine rechecking. Reuse completed shared
   inputs; prepare independent work without waiting for unrelated approval.
   Unchanged inputs should not require recreating a local adapter or reading
   validator source. Existing advanced and narrative routes remain available.

## Verification and stop conditions

- Focused positive and negative integration tests: human five-view, nonhuman,
  independent prop/scene, style capsule, stale/tampered input and failed review.
- Contrasting existing repair/narrative paths retain their behavior.
- Reuse checks cover an unchanged approved source consumed by another task and
  a reviewed candidate without a duplicate executor self-check. Changed pixels,
  truth, use, forged review or unresolved failure must still fail.
- Replay with the currently installed Jingzao provider in an isolated project;
  perform representative real image execution and review using public entries.
- Record required host turns, preparation/review wall time, actual generation
  and image defects separately. Compare like-for-like calls; do not claim a
  universal speedup from file counts or one successful image.
- Independent review and full project validation on the final candidate.
- Stop when a production task can prepare and record a representative batch
  through public commands without custom Python, manual hashes or schema repair,
  and output quality remains within the requested requirements.

## Scope and delivery

This plan authorizes local implementation and verification. Preserve the active
user production task and its artifacts. Do not change models or add providers,
required forms, service layers, schedulers or approvals. Release/install actions
follow the user's applicable authorization; report local and installed evidence
separately.
